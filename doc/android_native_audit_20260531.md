# 安卓管理端运营审查记录（2026-05-31）

## 审查目标

从运营管理角度复核安卓 App 的五个业务 Tab、详情页、弹窗动作、顶部统计卡片、更新机制与安全边界，重点判断是否能在移动端独立完成审批、发卡、回款、催收、平账和风控核查。

## 总体结论

当前安卓 App 已覆盖核心工作台能力：登录、档案、申请、发卡、回款、平账、详情查看、照片预览、风控报告、审核转单、审批、发卡、催收、平账、拉黑、解除位置风控等。主要问题不在“有没有页面”，而在运营口径、状态收口和升级安全上仍有几个会影响生产使用的点。

## 已发现并处理的问题

1. 平账 Tab 顶部统计第一张卡片显示 `--`，不符合财务管理需要。已改为展示待平账订单数量，第二张卡片继续展示已收金额，并补充其他费用金额提示。

2. 发卡 Tab 顶部第二张卡片原来展示今日发卡额，但发卡人员最需要优先判断“还有没有可用卡”。已改为展示可用卡池张数，并在提示中展示可用卡池总金额。

3. 申请 Tab 在切到全部、已通过、未通过时，仍可能露出审批通过、审批拒绝、调额等动作，存在误操作风险。已改为只有 `REVIEWING` 状态才展示审批相关动作，其他状态仅保留备注和黑名单处理。

4. 回款 Tab 原来无论状态如何都展示确认还款申请、展期、增额等动作，状态边界过宽。已改为只有存在还款申请次数时才展示确认还款申请，只有待付款或逾期订单才展示提醒、催收、展期和增额。

5. 平账 Tab 原来对非待还/逾期状态仍可能出现平账、结清、展期动作。已改为仅 `DISBURSED`、`OVERDUE` 状态展示财务处理动作；无动作时显示“当前状态暂无可执行操作”。

6. 档案详情中“刷新档案”按钮实际没有发起刷新接口，只会回到列表并提示完成，属于冗余且容易误导。已移除。

7. App 内更新流程缺少升级包校验。已增加 HTTPS 同域校验、包名校验、版本号校验和可选 SHA256 校验，避免版本清单或下载链路异常时安装错误包。

8. App 内更新遇到“未知来源安装权限”时，原流程只打开设置页，返回后不会自动继续安装。已改为缓存已下载 APK，用户授权后回到 App 会继续调起系统安装确认页。

9. 升级失败时生产使用不能中断。本次发布继续沿用生产备份策略，发布前备份当前 APK、下载页和版本清单，保留旧版回退路径。

## 页面审查摘要

### 档案

档案页适合做客户全局检索，详情页信息较完整，包含认证照片、核心信息、风控报告、联系人、位置、IP、订单审核批注和处理动作。需要注意的是，档案页不是订单处理主入口，因此已去掉无效刷新动作，保留拉黑、解除位置风控、二次发卡等确有运营价值的动作。

### 申请

申请页是审核人员主工作台。列表里展示申请时间、最新 IP、IP 位置、GPS 和 GPS 位置，对审核足够关键。详情页补充渠道、审核员、风控报告、照片和联系人，已具备移动端独立审批基础。本次重点修正状态动作边界，避免非审核中订单继续被审批。

### 发卡

发卡页的关键管理目标是“待发卡订单能否被卡池支持”。因此顶部统计从今日发卡额改为可用卡池张数/金额，更贴近发卡操作决策。列表和详情保留确认发卡、拒绝发卡、退回待下单、备注和拉黑。

### 回款

回款页顶部卡片继续围绕今日回款进度和逾期处理：未逾期时展示实际/应回款人数与今日到期金额，已逾期时展示累计逾期人数和逾期金额。本次收紧按钮逻辑，减少对已不适合处理状态的误触。

### 平账

平账页原顶部统计可读性不足，已经改为待平账订单和已收金额。平账弹窗中登记收款、减免、其他费用和预览区能支持当前财务口径，但实际还款日期仍未在安卓弹窗中显式提供，后续如果财务人员经常在手机端平账，建议补充“实际还款日期”选择项。

## 后续建议

1. 增加安卓端“实际还款日期”选择，避免财务手机端平账时无法按客户真实还款日冻结逾期费。

2. 回款日期筛选当前主要是端侧筛选，后续建议后端补充通用 due_date_start / due_date_end 参数，保证分页后仍然准确。

3. 增加移动端登录/操作审计页面，方便定位“网络异常、被挤下线、多端登录”等运营反馈。

4. 给原生安卓项目补充可执行的 JVM 单元测试或轻量截图巡检脚本，降低后续 UI 迭代回归风险。
