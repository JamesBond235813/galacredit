# 2026-09-05 22:00:00

## 项目当前进展

GalaCredit 当前采用 FastAPI 后端、Vue/UniApp 前端和 Android WebView/App-plus 交付路线。后端、管理端、用户 H5、UniApp 页面和 Android 构建链路均已存在，但“全部页面在真实 Android 设备上的最终像素级验收”尚未完成。

## 已完成内容

- 用户 H5 与 UniApp 登录流程已接通：Ghana 手机号、短信验证码、协议同意、滑块验证和登录态处理。
- Ghana Card 验证页源码已改为正面、反面两个上下排列的独立上传区域。
- UniApp 页面头部已统一使用自定义页面结构，并补充状态栏安全区；相关页面包括 verification、face、application、face-mismatch、orders、support、about。
- 页面头部重复返回按钮问题已处理：移除原生 WebView 注入的旧返回按钮，保留页面自身的圆形返回按钮。
- 底部导航已使用与 H5 相同的胶囊形导航样式。
- Android WebView 已设置不使用旧缓存（LOAD_NO_CACHE），APK 版本为 1.0.4 / versionCode 104。
- `frontend_uniapp` Vitest 当前记录为 13 个测试文件、41 个测试通过；H5 构建通过。
- 新版 UniApp H5 已发布到服务器 `/data/www/galacredit`，线上 `https://galacredit.ebamotor.com/` 返回 HTTP 200；发布前已创建远端备份。
- Samsung SM-F9660 已连接并成功安装 1.0.4 APK。

## 已确认的问题与边界

- 三星实机曾显示线上旧版本：顶部 Hello 文案被状态栏覆盖，且出现旧返回按钮。原因是线上 H5 未同步和 WebView 原生注入/缓存共同造成，而不是单一页面 CSS 问题。
- 重新发布线上 H5、修改 WebView 缓存策略并安装 1.0.4 后，实机登录页确认顶部状态栏不再覆盖品牌文案，登录页没有重复返回按钮。
- 实机曾成功进入 ID Verification 页面，并确认正面、反面两个上传区域已经显示；但该截图仍显示顶部圆形返回按钮过于靠近状态栏、底部固定提交区遮挡说明文案，随后已补充多个页面的顶部安全区。
- 第 3、4 项尚不能标记为最终完成：目前没有完成 19 个路由在同一台真实设备上的逐页截图、字体对照和滚动遮挡复核，也没有在最新发布版本上重新逐页验收。
- 当前已安装 APK 是 WebView 壳，页面视觉主要由线上 H5 决定；修改本地源码不会自动改变手机显示，必须构建、发布并让 WebView 重新加载线上资源。

## 当前风险

- 手机登录态在重启或重新安装后可能丢失，导致无法直接进入需要认证的验证页。
- 线上资源可能受浏览器/WebView 缓存影响，虽然 APK 已设置 LOAD_NO_CACHE，但仍需在设备上实际打开目标路由确认。
- 旧版原生壳和 UniApp app-plus 包曾同时存在，后续验收必须先确认包名、版本号和启动 Activity，避免把旧 APK 当成新版本。

## 下一步验收标准

1. 在 Samsung SM-F9660 上确认包版本 1.0.4 或更高，并重新登录。
2. 逐页检查 19 个路由：顶部状态栏/摄像头安全区、返回按钮、标题与正文层级、字体、底部胶囊 Tab、滚动和固定底部区域。
3. 对 ID Verification、Face Verification、Application、Home、Profile 等高风险页面保存实机截图，与 H5 同尺寸截图逐项比对。
4. 发现差异后继续修改、构建、发布、重载和复核，直到有截图证据支持“完成”。

## 结论

项目已达到“可构建、可发布、可在三星设备运行、核心登录和身份证双面页面已有源码修复”的阶段；尚未达到“全部 Android 页面完成真实设备像素级验收”的阶段。此前将局部验证结果表述为整体完成是不准确的。
