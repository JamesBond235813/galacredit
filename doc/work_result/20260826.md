### 修改说明

### 文档能解决的问题

1. 将安卓端采集的短信和已安装应用清单交给第三方平台做补充风险分析。
2. 用异步任务模式避免在申请接口中同步等待第三方计算。
3. 通过回调优先、轮询兜底，把第三方评分回写到本地风控决策流程。
4. 可作为设备环境、借贷压力、博彩/高风险应用等外部风险信号的一个输入来源。

### 关键接入风险与待确认项

- 文档要求上传短信正文、号码、时间和应用安装信息，属于高敏感数据；必须先完成用户授权、Google Play 权限合规、隐私政策、供应商数据处理协议和删除/保留规则确认。
- 创建接口的 `customer_secret_key` 直接放在 JSON 请求体中，生产环境必须只在后端保存和调用，不能放入 H5 或安卓客户端。
- 未说明回调签名、来源 IP 校验、重放防护、TLS 证书要求和回调幂等字段；接入前必须向供应商补齐。
- `task_score` 只有一个字符串分值，未给出分值范围、分数含义、阈值、命中原因、模型版本、错误重试语义；不能直接据此自动拒贷，应先映射为外部特征并进入 shadow/refer 流程。
- `request_id` 明确要求全局唯一且重复会报错；本地必须持久化请求号、任务号、订单号、状态和回调原文，支持幂等。
- 回调失败最多重试 5 次、超时 30 秒；本地回调接口应快速返回 200，将解析和决策联动放入异步任务。

## 安卓 App 风控策略集与前端实现评估

### 一、结论摘要

- 当前安卓 App `android_native` 是原生登录页 + WebView 业务页面，原生侧实际申请 `INTERNET`、粗略/精确定位权限；未实现短信读取、已安装应用清单、Root/模拟器/调试注入、硬件级设备指纹等采集。
- 当前 `frontend_h5` 已实现浏览器设备画像、设备指纹哈希、定位授权与上报、联系人选择、OCR/实名/人脸流程、登录/放款短信验证码；支持通过 `GalaCreditNative` 等桥接接收原生风险信号，但仓库内没有对应 Android JS bridge 实现。
- 后端已实现可解释的 `GHANA_CASH_LOAN_BASELINE` 策略、SHADOW/ENFORCE 模式、灰度、版本管理、决策日志和规则命中记录。现有规则以身份、黑名单、位置、逾期和设备信号为主；Fraud/Credit Score 的完整能力仍不是前端单独可完成的事项。

### 三、按“当前前端能否实现”归类

#### 已能实现或已有实现

1. 定位权限申请、定位上传和拒绝后的流程阻断/退出。
2. 浏览器基础画像：UA、浏览器版本、平台、屏幕尺寸、语言、时区。
3. 浏览器侧稳定设备指纹哈希（不能等同于硬件指纹）。
4. 身份证 OCR、人脸认证页面承载、联系人选择和格式/重复校验。
5. 登录和放款环节的短信验证码输入、倒计时和重发限制。
6. 风控结果、补件、人工审核结果的页面展示。
7. 通过原生桥接协议接收短信、应用清单、设备风险字段（协议已写，桥接实现缺失）。

#### 只能由后端/外部服务完成

黑名单、外部风险名单、KYC 最终判定、身份/人脸供应商核验、钱包实名和现金流、征信/AML、跨账号关联图、速度规则、Fraud/Credit Score、额度与 PTI/DTI、放款前二次校验、贷后催收和审计。

#### 当前安卓/前端明显缺口

- 没有 Android 原生风险桥接（`collectRiskSignals`/`getRiskSignals`）的实现与上报闭环。
- 没有可验证的 Root、模拟器、应用篡改、调试注入、VPN/代理、GPS mock 检测。
- 没有钱包供应商、征信机构、NIA/Ghana Card、AML/制裁名单生产凭据和适配器。
- 前端没有完整的风控决策结果协议（标准 `APPROVE/APPROVE_LOW/REFER/DECLINE/BLOCK` + reason codes）展示规范；当前主要依赖业务接口状态和后端处理。
- H5 不能直接读取短信全文或已安装应用；即使接入桥接，也必须取得同意、做数据最小化并通过 Google Play/隐私合规审查。

### 四、建议优先级

1. 先固定前后端决策协议：决策结果、1–3 个标准原因码、补件/申诉动作和放款前复核状态。
2. 完成 Android 原生桥接的最小版本：应用版本、设备完整性摘要、设备 ID 哈希、代理/VPN 和 mock location 信号；不恢复 `READ_SMS`。
3. 将设备信号、速度特征、钱包一致性接入后端 `risk_feature_snapshot`，继续使用 SHADOW 模式验证误杀率。
4. 接入并审计 Ghana Card/NIA、Mobile Money、征信和 AML 服务后，再逐步把规则从 shadow 灰度到 enforce。
