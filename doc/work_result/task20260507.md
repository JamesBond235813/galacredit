# `frontend_h5` 端及服务端功能改造
## 用户登录
1. 用户登录切换为使用手机短信验证码登录
   1. 下发短信验证码的功能在 `backend/app/services/sms_service.py` 中
   2. 短信验证码登录功能你之前已经在`backend/app/services/sms_auth.py` 中写过一部分代码，当时下发短信的行为被mock了， 现在需要实现。
   3. 用户登录界面中，要求有`发送验证码`按钮（或相应文案的按钮），点击该按钮时， 先弹出图形验证码界面， 验证通过后才执行下发短信请求/动作。
2. 图形验证码
   1. 图形验证码使用滑块的图形验证码。 服务端生成随机基底图片，中间镂空，让用户滑到指定的位置。
   2. 基底图片的宽度由前端向服务端上报， 为当前登录页顶级容器宽度的88%， 但要求有最小值，最小值由你自己确定。即，不论使用PC浏览器还是手机浏览吕，基底图片不能过小或过大。基底图片的高度由你判断给出固定值。
   3. 滑块图形仅在x轴上移动
   4. 滑块到指定的位置，误差绝对值可在.env中配置， 以px为单位， 默认为5
   5. 滑块移动到指定位置的时间有限制， 滑到指定位置的最短时间你给建议值

## 登录与邀请码联动 
1. 用户若访问含邀请码的链接进入页面， 要求在前端先记录邀请码。就算有跳转，邀请码信息也为能丢失，但可以被新邀请码覆盖。 邀请码为 `数字与小写字母组成的16位字符串`，不符合此规则的，不是邀请码， 可忽略。
2. 用户通过短信验证码登录
   1. 若用户不存在，则注册用户（新增用户）：
      - 如果此时如果有邀请码， 则通过邀请码查找对应`已启用`的渠道ID，并关联到该用户。
      - 若不包含邀请码， 或对应邀请码未找到`已启用`的渠道ID， 该用户不关联邀请码。
   2. 若用户已存在， 则走登录逻辑， 此时忽略邀请码（不管用户是否已关联渠道）

## 功能验证
1. 滑块验证的信息，在服务端使用内存缓存， 不可造成内存泄漏。
2. 发送短信验证码的功能， 仍支持mock配置
